# Frontend Docs Architecture

The public docs host serves the Docusaurus root docs app and both framework Storybooks from one origin.

## Public route shape

- `/` serves the Docusaurus docs app.
- `/design-system/react/` serves the independently built React Storybook.
- `/design-system/vue/` serves the independently built Vue Storybook.

## Delivery model

- Docusaurus provides the shared explanation and reference layer: tokens, package surfaces, curated component pages, route-level documentation, and simplified contract/reference samples.
- React Storybook provides the React implementation docs, stories, controls, and accessibility checks.
- Vue Storybook provides the Vue implementation docs, stories, controls, and accessibility checks.
- Interactive implementation behavior stays in Storybook instead of being duplicated in Docusaurus.

## Build outputs

The docs build assembles a same-origin static host by copying:

- the Docusaurus root build to `/`
- the React Storybook build to `/design-system/react/`
- the Vue Storybook build to `/design-system/vue/`

That keeps the deployed experience unified without coupling the framework Storybooks into one runtime.

## Operational notes

- The docs app remains the root host, owns the `/` route, and controls the mounted output paths.
- React and Vue Storybooks still build independently and can run as standalone workbenches in development.
- Same-origin mounting avoids the cross-origin Storybook ref issues that come with separate deployed origins.
