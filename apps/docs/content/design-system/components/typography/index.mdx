# Typography

Typography defines the shared text-style contract across the Hoite Dev design system.

This page focuses on the `@hoite-dev/ui` semantics, defaults, class output, and direct source links.

## Purpose

Typography gives product surfaces a stable text scale and semantic default mapping for React and Vue implementations to honor.

## Contract highlights

- `@hoite-dev/ui` defines the shared `variant` and `tag` contract.
- Each variant has an intentional default semantic tag.
- Shared CSS always emits the base `typography` class plus a variant-specific BEM modifier.

## Variant contract

Typography variants map to a default semantic tag and a stable class output. This matters directly for `@hoite-dev/ui` consumers using the shared CSS without a framework wrapper.

## Usage notes

- Default tag mappings are intentional and should usually stay intact.
- Override the tag only when the surrounding document outline or inline semantics require it.
- When consuming `@hoite-dev/ui` directly, apply both the base class and the matching modifier class.
- Keep playground controls focused on the visible API rather than non-visual attribute noise.
